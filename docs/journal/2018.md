# 2018 journal

## Day 1

- **Key idea:** part 2 never simulates the repeating stream. Each later
  frequency is a one-cycle prefix plus a whole number of cycle drifts, so two
  prefixes collide only when their difference is divisible by the drift. The
  earliest valid (cycles, position) pair gives the first repeat, and an input
  with no valid pair provably never repeats, so the search always terminates.
- **Surprise:** some part-1 examples never repeat under part 2. Those inputs
  render part 1 only, so the part-1 fixtures stay valid.
- **Primary measurement** (x86_64 Linux, pinned CPU 0): work median 93.5 M
  user-space instructions [92.8 M, 107.5 M], wall median 5.0 ms, peak RSS
  2208 KiB. The quadratic prefix-pair scan dominates.
- **Exploration `residue_buckets`:** sort the running totals from one pass by
  their remainder modulo the net change per pass (reflected when that change is
  negative). Within each group only neighbouring values can be the first
  repeat, because farther values need more passes, so it's O(n log n).
  Running totals must leave out the end of the pass, which equals the next
  pass's starting total; when the net change is 0, that start becomes the
  candidate. Measured: work median 0.79 M [0.07 M, 2.45 M] against the
  primary's 94.5 M, about 120 times less; wall median 1.6 ms against 5.2 ms;
  RSS about the same. Process startup dominates its wall time, and the work
  range is wide because the solver's work is near the empty-input subtraction
  noise. A worker's comparison with the primary on 19,530 short sequences
  matched every case.

## Day 2

- **Key idea:** part 1 is a per-ID letter histogram checked for exact counts
  of two and three. Part 2 compares every pair of IDs position by position and
  stops at the second mismatch, so most pairs end after a few letters.
- **Surprise:** the autommit critic split the parser change from the part-1
  solver, giving two commits for part 1. The commit policy needs to say how
  the critic's splits relate to "one commit per step".
- **Primary measurement** (x86_64 Linux, pinned CPU 0): work median 3.57 M
  user-space instructions [1.28 M, 4.17 M], wall median 1.6 ms, peak RSS
  2204 KiB. The wide work range comes from startup-subtraction noise at this
  scale, not the solver.

## Day 3

- **Key idea:** claims become half-open rectangles. Each covered square inch
  goes into a map that records whether more than one claim covers it. Part 1
  counts the shared cells; part 2 finds the only claim with no shared cell.
- **Surprise:** the statement says the fabric is *at least* 1000 inches wide,
  so the primary uses a sparse `HashMap` instead of assuming a fixed grid.
  Half-open ranges keep claims that only touch at an edge from counting as
  overlapping.
- **Primary measurement** (x86_64 Linux, pinned CPU 0): work median 155.4 M
  user-space instructions [141.9 M, 157.2 M], wall median 25.4 ms, peak RSS
  12412 KiB. The hash map dominates: about one hashed insert per claimed
  cell.
- **Exploration `dense_grid`:** a flat `u8` counter per cell, capped at 2,
  over the claims' bounding box with the origin subtracted. It uses checked
  row-major offsets, `get`/`get_mut` access, and allocation that can fail
  safely. Measured: work median 17.7 M [13.2 M, 17.9 M] against 156.3 M,
  about 9 times less; wall median 3.0 ms against 15.9 ms; peak RSS 3108 KiB
  against 12328 KiB. The trade-off is that memory follows the bounding box,
  not the number of covered cells, so a few claims far apart would cost a lot
  of memory. No vectorization claim: a worker's profile showed the time going
  to counter marking and checked offset arithmetic.

## Shared parsing (`aoc_core::parse_records`)

- Days 1 to 3 repeated "parse each line, collect them in order, reject empty
  input". That now lives in `aoc_core::parse_records`, which returns
  `RecordsError<E>` (`Empty` or `Line { line, source }`), and the day
  template uses it with borrowed `&str` records instead of `Vec<String>`.
- **Surprise:** the migration added 53 net lines across the three days. Each
  day now has a per-line error type, and its tests match nested error
  variants. The gains are line numbers in diagnostics and a template that no
  longer allocates each line; days written from now on start smaller. No
  derive macro: the remaining shared code is a two-line `Empty` variant, not
  enough to justify a proc-macro crate.
- Answers for days 1 to 3 were byte-identical before and after
  (`.cache/regression/003c60b/`).

## Day 4

- **Key idea:** sort timestamped events before reducing guard-state transitions
  to half-open midnight sleep intervals. Each guard gets a 60-minute histogram.
  Total sleep selects the guard for the first strategy; the second selects the
  largest individual guard/minute count.
- **Surprise:** wake minutes must stay excluded, and a shift can begin on the
  previous evening. Chronology and transition validation belong in the parser,
  leaving the solver to count validated intervals. Exhaustive interval checks
  cover all 1,770 nonempty midnight ranges.
- **Cost:** O(n log n + s log g + 60s + 60g) time and O(n + 60g) memory for
  n records, s sleep intervals, and g sleeping guards. Two full record passes
  cover parsing and chronological reduction, in addition to sorting and the
  interval and histogram traversals.
- **Primary measurement** (x86_64 Linux, release, pinned CPU 0, revision
  `4f83b0c`): five full/empty pairs give work median 1,784,270 user-space
  instructions [1,063,609, 4,036,594]. Ten timing runs give wall median
  2,104 us [2,032, 2,267], CPU median 0 us [0, 0], and peak RSS 2,264 KiB.
  CPU time is below GNU time's 10 ms resolution, not zero computation.
  Work subtraction is noisy at this scale; wall includes process launch and
  redirected I/O. No speedup or dominant-code-path claim is supported by this
  measurement. The host had load averages below 1.5 across 12 logical CPUs.
- **Documentation lesson:** scaffold test names describe raw borrowed lines,
  but a validated domain can replace those lines with chronological intervals.
  Their retained test identities no longer describe every assertion precisely.

## Day 5

- **Key idea:** a byte stack of unreacted units. Each new unit either cancels
  the stack top (same letter, opposite case) or is pushed, so cascades that
  expose earlier neighbours never need a rescan. Part 2 reruns the reduction
  once per unit type with that type filtered out, reusing the stack storage.
- **Cost:** O(26n) time, O(n) memory.
- **Primary measurement** (x86_64 Linux, pinned CPU 0, revision `ff3e6d2`):
  work median 46.8 M [40.5 M, 47.5 M], wall median 6.5 ms, peak RSS 2184 KiB.
  The 27 reductions over a 50 KB polymer dominate.

## Day 6

- **Key idea:** enumerate the sites' bounding box and give each cell to its
  unique nearest site. A site that owns a boundary cell owns an infinite
  region and is excluded. The safe region in part 2 can extend past the
  sites, so its search area is widened by the distance limit divided by the
  site count.
- **Surprise:** the statement's part-2 example uses a smaller limit than the
  real puzzle. The fixture keeps the production limit, and its expected value
  came from an independent scratch reference.
- **Cost:** O(n·W·H) time, O(n) memory; no grid is stored.
- **Primary measurement** (revision `42f19ec`): work median 436.6 M
  [422.9 M, 446.2 M], wall median 16.0 ms, peak RSS 2212 KiB. That is the
  heaviest of days 5 to 10. Every cell compares against every site in both
  parts; [?!] a distance transform or per-site sweep would cut it, which makes
  this a natural exploration.

## Day 7

- **Key idea:** repeatedly take the alphabetically first step whose
  prerequisites are complete. `BTreeMap`/`BTreeSet` make the tie-break the
  container order. Part 2 is an event-driven simulation where idle workers
  claim available steps in that same order.
- **Cost:** O(V(V+E)) time, O(V+E) memory.
- **Primary measurement** (revision `6628e8b`): work median 0.83 M
  [0.75 M, 1.59 M], wall median 1.4 ms, peak RSS 2212 KiB. The run is close to
  process-startup noise.

## Day 8

- **Key idea:** parse the header/children/metadata tree with an explicit
  stack into flat child-before-parent nodes, so recursion depth never depends
  on the input. Metadata sums and child-indexed values then come from one
  postorder walk. Child references that are 0 or out of range count as 0.
- **Cost:** O(n) time and memory.
- **Primary measurement** (revision `1ccc65e`): work median 7.35 M
  [3.61 M, 7.84 M], wall median 1.7 ms, peak RSS 2456 KiB.

## Day 9

- **Key idea:** a `VecDeque` holds the circle with the current marble at the
  back. Placing a marble rotates by a constant 1 or 2, and a scoring turn
  rotates back by 7, so every move is O(1) amortized. That makes part 2's
  hundredfold game feasible without a linked list or index arithmetic.
- **Cost:** O(m + p) time and memory for m marbles and p players.
- **Primary measurement** (revision `8f44ffc`): work median 935.4 M
  [895.2 M, 936.4 M], wall median 84.6 ms, peak RSS 68032 KiB. Part 2's
  millions of deque rotations and the circle's storage dominate both work and
  memory.
- **Optimization (`b36a504`):** profiling showed 60% of the time in
  `VecDeque::rotate_left_inner` and `memmove`. A generic rotate pays
  bookkeeping and copy setup even for a distance of 1. The primary now moves
  single marbles with `pop_front`/`push_back` (and back for the 7-step
  rewind), stores marbles as `u32` instead of `u64`, and reserves the whole
  circle once. The algorithm is the same and the answers are identical.
  Measured: work median 409.9 M [409.5 M, 410.3 M] against 935.4 M (2.3 times
  less), wall median 21.8 ms against 84.6 ms, peak RSS 29732 KiB against
  68032 KiB. After the change, `perf` shows more than 92% of samples in the
  inlined `high_score` loop, with no rotation or `memmove` symbols left.
  Marbles above `u32::MAX` are rejected with a typed error.

## Day 10

- **Key idea:** the message appears when the lights are most compact. The
  bounding-box perimeter is convex in time for linear motion, so exponential
  bracketing plus binary search finds its first minimum with exact integers
  and no guessed time horizon. Part 2 is that time.
- **Answer rendering:** part 1's answer is letters drawn by lights. The
  solution renders the converged raster on line 1 (rows joined by `/`, `#` lit),
  and a person reads the glyphs for submission. There's no OCR and no
  hardcoded letters.
- **Surprise:** AoC writes this day's examples as raw `position=< 9,  1>`.
  The statement extractor took every `<` as a tag opener and silently deleted
  all 31 example lines. `aoc-ops` now treats `<` as markup only before a
  letter, `/` or `!`, as HTML does (`749adbf`). Refreshing days 1 to 9 left
  their cached statements byte-identical.
- **Cost:** O(n log t + A log n) time, O(n + A) memory for n lights,
  convergence time t and rendered area A.
- **Primary measurement** (revision `5270556`): work median 1.24 M
  [0.57 M, 3.22 M], wall median 1.5 ms, peak RSS 2172 KiB. The logarithmic
  search keeps it at startup-noise level.

## Day 11

- **Key idea:** a summed-area table gives each square's total in constant
  time. Exhaustive enumeration of sizes and origins then finds the optimum
  without assuming which square size wins.
- **Cost:** O(N³) time, O(N²) memory for grid width N.
- **Primary measurement** (revision `351ea79`): work median 112.5 M
  [112.5 M, 112.5 M], wall median 33.8 ms, peak RSS 2704 KiB. Enumerating
  every square remains cubic even though each total is constant-time.

## Day 12

- **Key idea:** evolve simultaneous neighbourhood rules, normalize each plant
  shape by its leftmost position, and skip cycles only after exact shape
  equality proves a translation.
- **Surprise:** apparent stabilization is not a proof of a cycle. Rules that
  grow plants from an empty neighbourhood are rejected because they would
  produce infinite growth outside the represented finite state.
- **Cost:** O(g w log n + g n log g) time, O(g n) memory for g generations
  before a repeat, scanned width w, and at most n plants per generation.
- **Primary measurement** (revision `f0e7574`): work median 12.9 M
  [12.9 M, 17.9 M], wall median 25.6 ms, peak RSS 2184 KiB. Work depends on
  how many generations and normalized shapes precede the first exact repeat.

## Day 13

- **Key idea:** preserve map whitespace and move carts in reading order,
  removing colliding pairs immediately. Separate pending and moved maps ensure
  that a removed cart never takes its turn. Repeated states reject maps that
  never resolve.
- **Surprise:** the first submission was rejected after an answer was retyped
  incorrectly from a compacted screenshot of tool output. An independent
  reference confirmed that the primary was right. Answers are now submitted
  from captured stdout files, never retyped.
- **Cost:** O(S log S + T C log(S C T)) time, O(S + T C) memory for S track
  cells, T ticks, and at most C carts.
- **Primary measurement** (revision `69b4b5b`): work median 62.7 M
  [54.4 M, 62.7 M], wall median 20.9 ms, peak RSS 4228 KiB. Ordered cart
  updates and stored cycle states make the cost depend on the simulated ticks.

## Day 14

- **Key idea:** retain the scoreboard for cursor movement and compare each new
  candidate start directly with the input digits. Keep the decimal input token
  separate from its numeric interpretation so leading zeros survive the search.
- **Cost:** O(L m) time, O(L + m) memory for L generated recipes and m input
  digits. Direct comparisons avoid matcher preprocessing.
- **Primary measurement** (revision `03fdcd9`): work median 2.06 G
  [2.06 G, 2.13 G], wall median 285.3 ms, peak RSS 21900 KiB. The generated
  scoreboard's length drives both candidate comparisons and retained storage.

## Day 15

- **Key idea:** simulate reading-order turns with BFS for destination and
  first-step tie-breaks. Stable unit IDs prevent dead units' turn slots from
  being reused, and only completed rounds count.
- **Surprise:** ascending power search avoids assuming that battle outcomes
  are monotone. The search cap follows from attacks killing in one hit, beyond
  which additional power cannot change an attack's effect.
- **Cost:** O(A R U V log V) time, O(V + U) memory for A powers, R rounds,
  U units, and V cells. Ordered sparse maps make the tie-breaks explicit.
- **Primary measurement** (revision `d4d32b6`): work median 18.37 G
  [17.15 G, 18.45 G], wall median 2479.6 ms, peak RSS 2176 KiB. Repeated
  path searches across the ascending power trials drive the work.

## Day 16

- **Key idea:** intersect each opcode's candidate meanings across observations,
  then solve the bijection with bounded backtracking before executing the
  program. Singleton elimination alone need not settle every constraint.
- **Cost:** O(samples · 16 + search + program) time, O(samples + program)
  memory. The bijection search has a factorial worst case.
- **Primary measurement** (revision `863c553`): work median 9.13 M
  [8.70 M, 9.39 M], wall median 1.6 ms, peak RSS 2300 KiB. Wall time is near
  process-startup scale despite the candidate tests and bijection search.

## Shared device (`device.rs`)

- **Key idea:** extract the opcode implementation on its second real use,
  day 19, rather than anticipate a shared interpreter on day 16. Operations
  execute against register slices; bound-pointer programs write the pointer
  before execution, then read it back before incrementing.
- `Program::parse` validates the binding and register operands.
  `Program::step` advances `Machine { registers, ip }`, with checked arithmetic
  and register bounds reported through `DeviceError`.
- Day 16's answers were byte-identical before and after the extraction
  (`.cache/regression/52ed3b2/`).

## Day 17

- **Key idea:** descend until supported, spread across the support, and revisit
  water above newly settled rows. Sparse cells avoid a coordinate-sized grid,
  and an explicit work stack avoids recursive call depth.
- **Cost:** O(C + W²) worst-case time, O(C + W) memory for C clay cells and
  W wet cells.
- **Primary measurement** (revision `325726c`): work median 89.4 M
  [88.7 M, 99.7 M], wall median 9.1 ms, peak RSS 7200 KiB. Revisited water
  rows can require repeated scans as support settles below them.

## Day 18

- **Key idea:** apply simultaneous acre rules and skip only exactly repeated
  full states, not repeated resource values.
- **Surprise:** a cycle-search bound is a resource limit, not a guarantee that
  a repeat exists within it. Exhausting the state or byte limit returns the
  typed `NoCycle` error rather than guessing a period.
- **Cost:** O((transient + period) · acres) expected time and memory when a
  cycle is found within the resource limits.
- **Primary measurement** (revision `431e0c0`): work median 369.3 M
  [349.2 M, 370.0 M], wall median 17.7 ms, peak RSS 4204 KiB. Full-grid
  updates and retained exact state keys scale with the time to the first repeat.

## Day 19

- **Key idea:** run both initial states on the shared device. Recognize an
  exact divisor-enumeration loop and replace it with a divisor sum, accounting
  for register renaming rather than relying on fixed register numbers.
- **Surprise:** acceleration checks the entire loop and its distinct register
  roles. Programs that fail those checks fall back to interpretation.
- **Cost:** O(prefix + √target + suffix) time with a recognized loop,
  O(program) memory. Unrecognized programs retain interpreter cost.
- **Primary measurement** (revision `da24d6b`): work median 0.23 M
  [-0.61 M, 0.95 M], wall median 1.6 ms, peak RSS 2164 KiB. Startup
  subtraction noise exceeds the accelerated solver's work, so the negative
  minimum is measurement noise, not negative computation.

## Day 20

- **Key idea:** track branch frontiers with an explicit stack, deduplicate
  converging endpoints, and build a door graph. BFS then gives shortest paths.
  Nesting depth never becomes call-stack depth.
- **Cost:** two input passes; O(T log R + R log R) time, O(R + S) memory for
  T endpoint steps, R rooms, and S saved endpoints.
- **Primary measurement** (revision `13b68d3`): work median 40.3 M
  [40.3 M, 48.0 M], wall median 6.2 ms, peak RSS 5356 KiB. Branch-frontier
  expansion and ordered-set deduplication drive graph construction cost.

## Day 21

- **Key idea:** observe halt-comparison candidates until the full machine
  state repeats, rather than assuming that a repeated candidate proves a
  cycle. A checked division-loop replacement accelerates execution without
  changing device semantics.
- **Surprise:** the statement provides no examples, so there are no statement
  fixtures for this day.
- **Cost:** O(executed non-division instructions) time,
  O(program + comparison states) memory with the checked acceleration.
- **Primary measurement** (revision `a107dbb`): work median 48.2 M
  [39.7 M, 48.2 M], wall median 3.9 ms, peak RSS 3520 KiB. The remaining
  interpreted instructions and stored comparison states scale with the cycle.

## Day 22

- **Key idea:** grow an erosion cache on demand and use A* over position and
  equipment states. Manhattan distance plus the required torch switch is an
  admissible heuristic; no guessed coordinate bound can exclude a better route.
- **Cost:** O(A + S log S) time, O(A + S) memory for cached area A and
  searched states S.
- **Primary measurement** (revision `d646105`): work median 523.2 M
  [492.1 M, 525.3 M], wall median 45.6 ms, peak RSS 16656 KiB. The explored
  state space determines priority-queue work and erosion-cache growth.

## Day 23

- **Key idea:** exact best-first cube subdivision uses coverage upper bounds
  and origin-distance lower bounds to discard regions that cannot improve the
  result. The search makes no assumption about the input's shape.
- **Cost:** O(n V + V log V) time, O(n + V) memory for n transmitters and
  V visited cubes, with two input passes. Loose bounds can force exponentially
  many subdivisions.
- **Primary measurement** (revision `e2ebf39`): work median 94.6 M
  [83.3 M, 95.2 M], wall median 5.7 ms, peak RSS 2300 KiB. Bound tightness
  controls how many cubes require coverage tests and queue operations.

## Day 24

- **Key idea:** select targets by damage and power, then apply attacks in
  initiative order. A round with no kills is a stalemate, not a win.
- **Surprise:** exhaustive ascending boost search proves minimality without
  assuming monotone battle outcomes.
- **Cost:** O(B R G² + B R G log G) time, O(G) memory for B boosts,
  R rounds, and G groups.
- **Primary measurement** (revision `0270c97`): work median 634.5 M
  [634.1 M, 635.5 M], wall median 27.8 ms, peak RSS 2260 KiB. Repeated
  target selection across boost trials drives the work while battles reuse
  group-sized storage.

## Day 25

- **Key idea:** flood-fill the implicit graph whose edges join points within
  the distance threshold. Scan remaining points instead of storing edges or
  maintaining disjoint-set indices. This day has only a computational part 1.
- **Cost:** O(n²) time, O(n) memory for n points.
- **Primary measurement** (revision `83f6896`): work median 19.6 M
  [15.9 M, 20.2 M], wall median 4.2 ms, peak RSS 2264 KiB. Pairwise distance
  checks drive the quadratic work without requiring quadratic edge storage.
